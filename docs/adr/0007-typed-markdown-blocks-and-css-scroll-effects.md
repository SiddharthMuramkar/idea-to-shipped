# Lesson blocks are typed fenced Markdown, not MDX, and scroll effects are CSS plus IntersectionObserver, not an animation library

Lessons now hold goals, Scenes, Checkpoints, a Final test, callouts, exercises, a Site story and sources. Each one is written as a fenced code block whose first word names its kind (```` ```checkpoint who-owns-details ````). The Lessons module parses and checks these blocks at build time, so a broken Lesson fails the build and the error names the file, the block and the id. We chose this over MDX because a Lesson file stays plain Markdown: any editor or agent can write it, GitHub shows each block as readable text, content can't import components or run code, and all the page's React stays in one place. Scroll effects follow the same progressive-enhancement approach as the existing Reveal and photo-band parallax. Continuous effects (the reading progress line, rising headings, highlight sweeps, parallax) are CSS scroll-driven animations. The few effects that need state (stepping a Scene, tracking the current Section and its tone) each use one small IntersectionObserver in a client island. We rejected an animation library such as GSAP or Motion, because it would add tens of kilobytes and scroll listeners for effects the browser can now run itself. The cost: browsers without scroll-driven animations (Firefox before 159) show those effects at their final state instead of moving. This reverses no earlier decision. It records why the obvious tools weren't used.
