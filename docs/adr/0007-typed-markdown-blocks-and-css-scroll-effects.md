# Lesson blocks are typed fenced Markdown, not MDX, and scroll effects are CSS plus IntersectionObserver, not an animation library

Lessons hold goals, Scenes, Checkpoints, a Final test, callouts, exercises, a Site story and sources. Each one is written as a fenced code block whose first word names its kind (```` ```checkpoint who-owns-details ````). The Lessons module parses and checks these blocks, so a broken Lesson fails the build and the error names the file, the block and the id. We chose this over MDX because a Lesson file stays plain Markdown: any editor or agent can write it, GitHub shows each block as readable text, content can't import components, and all the page's React stays in one place. The parser also refuses raw HTML, so a Lesson's content is only Markdown and typed blocks.

Scroll effects are progressive enhancement, with no animation library. A continuous effect is a CSS scroll-driven animation, and an effect that needs state uses one small IntersectionObserver in a client island. We rejected an animation library such as GSAP or Motion, because it would add tens of kilobytes and scroll listeners for effects the browser can now run itself. The cost: browsers without scroll-driven animations (Firefox before 159) show the photos without their parallax. This reverses no earlier decision. It records why the obvious tools weren't used.

**Partly built.** Two effects exist: the photo-band parallax (a CSS scroll-driven animation) and the fade-ins as content scrolls into view (one IntersectionObserver). The rest was planned under this decision and never built: stepping a Scene as you scroll, pinning its stage, a section bar with a reading progress line, rising headings and the highlight sweep. Every Scene shows its final state, with its steps as numbered captions.
