# Answers reference questions by permanent ids, with no foreign key

**Accepted, not built.** Nothing stores Answers yet: every question shows its own answer in a "Show the answer" box, and nothing is graded or saved. The code for this decision, an answers table and the quiz endpoints, is parked in git tag `wip/pr-a-2026-10-23`.

An Answer is one Visitor's pick of an option for one question. Questions live in Lesson files and Answers will be rows in Neon, so Postgres can't enforce the link between them. This is the same situation as Comments in ADR 0004. Each Answer will store three plain-text keys: the Lesson's slug, the question's id and the option's id. A question id is written on its block (`checkpoint who-owns-details`). It is kebab-case and unique within its Lesson, and Checkpoints and the Final test share one set of ids. An option's id is its position, `a` to `d`. We protect the link with a rule, extending ADR 0004's rule for slugs: once a Lesson is published, a question id is never renamed or reused, and a question's options are never reordered or removed. Rewording a question or an option is fine. Changing what a question asks, or which options it offers, means giving it a new id. The rule applies already, so that Answers can attach to today's questions once they're built. Each Answer will also store whether it was correct when it was given, and each Attempt (one go at a whole Final test) will store its score. So fixing a wrong answer key only changes future grades: old Answers and old passes keep the grade they got at the time. We rejected regrading on read, because it would silently flip a Visitor's past result. We rejected moving questions into the database for the same reason ADR 0004 gives for Lessons: a table, migrations and in-database editing, just to guard against a rename that should never happen.
