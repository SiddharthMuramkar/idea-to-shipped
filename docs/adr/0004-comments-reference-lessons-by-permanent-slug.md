# Comments reference file-based Lessons by a permanent slug, with no foreign key

Lessons are Markdown files and Comments are rows in Neon, so Postgres can't enforce the link between them. Each Comment stores its Lesson's slug as plain text, and the comments module refuses a slug that names no Lesson. We protect the link with a rule, not a constraint: a slug never changes once it's published, and a test fails if any published slug stops naming a Lesson. A Lesson's place in the order comes from its Course's `course.md`, never from its slug, so Lessons can be reordered, or moved to another Part or Course, without touching a Comment. We rejected moving Lessons into the database to get a real foreign key, because for a personal site that means a table, migrations and in-database editing just to guard against a rename that should never happen.

When this was decided (2026-10-21), the site had 11 Lessons, each placed by an `order:` header that its filename prefix matched (`01-grilling.md`). Today each Lesson's file is named after its slug, and ADR 0008 keeps one slug per Lesson across every Course.
