# Comments reference file-based Lessons by a permanent slug, with no foreign key

Lessons are Markdown files and Comments are rows in Neon, so Postgres can't enforce the link between them. Each Comment stores its Lesson's slug as plain text. We protect that link with a rule, not a constraint: a slug never changes once it's published. A Lesson's slug and position number come from its file's header (`slug:` and `order:`), never from the filename. The filename prefix (`01-grilling.md`) only keeps files sorted on disk and should match `order`. Position numbers never go in the slug, so lessons can be reordered safely. We rejected moving Lessons into the database to get a real foreign key, because for an 11-lesson personal site that means a table, migrations and in-database editing just to guard against a rename that should never happen.
